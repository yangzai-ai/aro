# v1.7 业务系统对接

> 供 Codex 实现。让业务前端可以轻松集成 ARO，无需理解内核细节。

日期：2026-11-11。前置：v1.6（c178bfb）。理由见 decisions-v1.4.md D7。

---

## 背景

当前状态：
- SSE 事件是隐式协议（代码即协议），没有正式文档
- Trace 只在内存（TraceHook），无查询 API
- 业务前端需要自己实现 SSE 解析、事件处理、重连逻辑
- 工作台是紧耦合的单体应用，无法复用

v1.7 目标：
1. **SSE 事件协议正式文档**：版本化，让业务后端可以透传
2. **Trace 查询 API**：让业务前端可以展示执行轨迹
3. **`@aro/client` + `@aro/react`**：可复用的协议层和组件层

典型部署架构：`业务前端 → 业务后端（代理） → ARO`

## 任务 1：SSE 事件协议文档

### 1.1 当前事件类型梳理

核心代码审查发现以下事件类型：

| 事件类型 | 数据字段 | 触发时机 | 来源 |
|---------|---------|---------|-----|
| `token` | `delta: str` | 模型生成文本 token | streaming.py |
| `reasoning` | `delta: str` | 模型思考过程（DeepSeek） | streaming.py |
| `tool_call` | `call_id, tool_name, args` | 工具调用开始 | loop.py |
| `tool_result` | `call_id, tool_name, args, success, result, error, duration_ms, approval_duration_ms, execution_duration_ms, hook_errors` | 工具调用完成 | loop.py |
| `agent_start` | `agent_name, parent_call_id` | 专家代理启动 | multiagent/handle.py |
| `agent_done` | `agent_name, parent_call_id, trace` | 专家代理完成 | multiagent/handle.py |
| `agent_failed` | `agent_name, parent_call_id` | 专家代理失败 | multiagent/handle.py |
| `agent_token` | `delta, agent_name, parent_call_id` | 专家代理生成 token | multiagent/handle.py (转发) |
| `agent_reasoning` | `delta, agent_name, parent_call_id` | 专家代理思考 | multiagent/handle.py (转发) |

### 1.2 协议文档结构

新建 `docs/protocols/sse-events-v1.md`：

```markdown
# ARO SSE 事件协议 v1

版本：1.0.0  
日期：2026-11-11  
状态：Stable

## 协议格式

所有事件遵循 [Server-Sent Events (SSE)](https://html.spec.whatwg.org/multipage/server-sent-events.html) 规范：

\`\`\`
event: <event_type>
data: <JSON_payload>

\`\`\`

- `event_type`：事件类型字符串
- `JSON_payload`：事件数据（JSON 对象）

敏感字段（api_key、password 等）会自动脱敏为 `[redacted]`。

## 核心事件

### 1. token

**用途**：模型生成的文本片段（逐字流式）

**数据**：
\`\`\`json
{
  "delta": "string"  // 本次生成的文本片段
}
\`\`\`

**示例**：
\`\`\`
event: token
data: {"delta": "根据"}

event: token
data: {"delta": "查询"}
\`\`\`

---

### 2. reasoning

**用途**：模型的思考过程（DeepSeek 协议扩展）

**数据**：
\`\`\`json
{
  "delta": "string"  // 思考过程片段
}
\`\`\`

---

### 3. tool_call

**用途**：工具调用开始

**数据**：
\`\`\`json
{
  "call_id": "string",           // 调用 ID（UUID）
  "tool_name": "string",         // 工具名称
  "args": { }                     // 工具参数（JSON 对象）
}
\`\`\`

**示例**：
\`\`\`json
{
  "call_id": "abc123",
  "tool_name": "query_tickets",
  "args": { "status": "open" }
}
\`\`\`

---

### 4. tool_result

**用途**：工具调用完成

**数据**：
\`\`\`json
{
  "call_id": "string",
  "tool_name": "string",
  "args": { },
  "success": boolean,
  "result": any | null,          // 成功时的结果
  "error": string | null,        // 失败时的错误信息
  "duration_ms": number,         // 总耗时（毫秒）
  "approval_duration_ms": number | null,  // 审批耗时
  "execution_duration_ms": number,        // 执行耗时
  "hook_errors": [               // Hook 错误（如有）
    { "hook": "string", "error": "string" }
  ]
}
\`\`\`

---

### 5. agent_start

**用途**：专家代理启动（多 Agent 场景）

**数据**：
\`\`\`json
{
  "agent_name": "string",
  "parent_call_id": "string"
}
\`\`\`

---

### 6. agent_done

**用途**：专家代理完成

**数据**：
\`\`\`json
{
  "agent_name": "string",
  "parent_call_id": "string",
  "trace": { }                   // AgentTrace 对象
}
\`\`\`

---

### 7. agent_failed

**用途**：专家代理失败

**数据**：
\`\`\`json
{
  "agent_name": "string",
  "parent_call_id": "string"
}
\`\`\`

---

### 8. agent_token / agent_reasoning

**用途**：专家代理的 token 和思考（转发自专家）

**数据**：
\`\`\`json
{
  "delta": "string",
  "agent_name": "string",
  "parent_call_id": "string"
}
\`\`\`

## 协议版本管理

- 当前版本：`v1` (1.0.0)
- 向后兼容：增加字段不改版本号，删除字段或改字段语义则升大版本号
- 客户端通过 `Accept` 头指定版本（预留，当前未实现版本协商）

---

## 安全与脱敏

所有事件数据在发送前自动脱敏：
- 字段名包含 `api_key`、`password`、`authorization`、`access_token` 等 → `[redacted]`
- URL 中的用户名密码（`https://user:pass@host`）→ `https://[redacted]@host`
- 配置的敏感值（通过 settings.secrets）→ `[redacted]`

---

## 业务后端透传

业务后端可以直接转发 ARO 的 SSE 流，无需解析或修改事件：

\`\`\`python
# FastAPI 示例
@app.get("/api/chat/{session_id}/stream")
async def proxy_stream(session_id: str):
    async with httpx.AsyncClient() as client:
        async with client.stream("GET", f"http://aro:8000/sessions/{session_id}/stream") as response:
            async for line in response.aiter_lines():
                yield line + "\n"
\`\`\`

---

## 扩展事件（未来）

预留以下事件类型（当前未实现）：
- `approval_required`：需要人工审批
- `session_restored`：会话已恢复
- `error`：执行错误

新增事件类型不会破坏现有客户端（忽略未知事件类型即可）。
\`\`\`

## 任务 2：Trace 查询 API

### 2.1 API 设计

新增两个查询接口：

**GET /traces/{trace_id}**
- 获取单个 Trace
- 返回：AgentTrace JSON

**GET /sessions/{session_id}/traces**
- 获取会话的所有 Trace
- 返回：AgentTrace[] JSON
- Query 参数：
  - `limit`：最多返回多少条（默认 50）
  - `offset`：跳过多少条（分页）

### 2.3 实现方案

**Phase 1（v1.7 最小实现）**：
- TraceHook 已在内存存储 traces
- api/traces.py 从 Engine 的 TraceHook 读取

- Trace 持久化插件（类似会话持久化）
- 支持跨重启查询

```typescript
// src/types.ts
export type AroEventType = 
  | 'token' 
  | 'reasoning' 
  | 'tool_call' 
  | 'tool_result'
  | 'agent_start'
  | 'agent_done'
  | 'agent_failed'
  | 'agent_token'
  | 'agent_reasoning';

export interface AroEvent<T = any> {
  type: AroEventType;
  data: T;
}

export interface TokenEvent {
  delta: string;
}

export interface ToolCallEvent {
  call_id: string;
  tool_name: string;
  args: Record<string, any>;
}

export interface ToolResultEvent {
  call_id: string;
  tool_name: string;
  args: Record<string, any>;
  success: boolean;
  result?: any;
  error?: string;
  duration_ms: number;
  approval_duration_ms?: number;
  execution_duration_ms: number;
  hook_errors: Array<{ hook: string; error: string }>;
}

// src/client.ts
export class AroClient {
  constructor(options: {
    baseUrl: string;
    token?: string;
  });

  /**
   * 发起对话并监听事件流
   */
  async chat(sessionId: string, message: string, options?: {
    onEvent?: (event: AroEvent) => void;
    onToken?: (delta: string) => void;
    onToolCall?: (call: ToolCallEvent) => void;
    onToolResult?: (result: ToolResultEvent) => void;
    onError?: (error: Error) => void;
  }): Promise<void>;

  /**
   * 创建新会话
   */
  async createSession(config: {
    target_agent?: string;
    tenant_id?: string;
  }): Promise<{ session_id: string }>;

  /**
   * 查询 Trace
   */
  async getTrace(traceId: string): Promise<AgentTrace>;

  /**
   * 列出会话的 Trace
   */
  async listTraces(sessionId: string, options?: {
    limit?: number;
    offset?: number;
  }): Promise<AgentTrace[]>;
}
```

## 关键设计点

1. **协议文档是正式规范**：业务后端按文档透传，不依赖 ARO 内部实现
2. **Trace API 先从内存读**：v1.7 不做持久化，未来可扩展
3. **npm 包独立发布**：`@aro/client` 和 `@aro/react` 独立版本
4. **工作台作为示例**：演示如何使用组件库，不是必选部署
5. **向后兼容**：新增字段不破坏现有客户端
