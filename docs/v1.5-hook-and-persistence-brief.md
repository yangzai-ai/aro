# v1.5 Hook 完整化与会话持久化

> 供 Codex 实现。回归两个扩展点架构：BaseTool + Hook（完整生命周期）。
> 原则：一个内核，两个扩展点，Capability 是打包器，所有能力（Trace/持久化/HITL）无特例。

日期：2026-11-10。前置：v1.4（031165f）。理由见 decisions-v1.4.md D2。

---

## 背景

讨论"持久化是否做成插件"时发现设计逐渐复杂化，引入了"宿主级基础设施"概念，准备为会话存储和 Trace 单独建扩展组。这偏离了最初的**一个内核、两个扩展点（BaseTool + Middleware）**设计哲学。

核心澄清：Trace、会话存储都能基于这两个扩展点实现。现有 Middleware 只覆盖轮级钩子（before/before_tool/after_tool/after），缺少装配期和关闭期钩子。补齐后，所有能力用同一套机制。

---

## 架构决定

```
内核
├── 扩展点 1：BaseTool（模型按需调用）
└── 扩展点 2：Hook（完整生命周期，所有能力用这一套）

Capability = 打包器（Tool + Hook 的任意组合）
```

现有 Middleware 完全兼容，就是只用了 Hook 中间四个阶段的能力。

---

## 第一部分：Hook 完整化

### 1. 定义 Hook 协议

新建或修改 `core/kernel/hook.py`（或直接在 `middleware.py` 里扩展）：

```python
class Hook(Protocol):
    """完整生命周期钩子。所有方法可选，默认空操作。"""
    
    async def on_start(self, config: dict) -> None:
        """引擎启动时：配置校验、连接建立。"""
    
    async def on_session_load(self, session_id: str) -> AgentState | None:
        """轮开始前：会话恢复。返回 AgentState 或 None。
        内核遍历所有 Hook，第一个返回非 None 的即用，其余跳过。"""
    
    async def before(self, state: AgentState) -> AgentState:
        """每轮开始（现有 Middleware.before）"""
    
    async def before_tool(
        self, tool_name: str, tool_args: dict, state: AgentState
    ) -> tuple[bool, str | None]:
        """工具执行前（现有 Middleware.before_tool）"""
    
    async def after_tool(
        self, tool_name: str, tool_args: dict, tool_result: ToolResult, state: AgentState
    ) -> AgentState:
        """工具执行后（现有 Middleware.after_tool）"""
    
    async def after(self, state: AgentState) -> AgentState:
        """每轮结束：写盘、Trace 导出（现有 Middleware.after）"""
    
    async def on_session_close(self, session_id: str) -> None:
        """会话关闭：删除存储。"""
    
    async def on_stop(self) -> None:
        """引擎停止时：连接释放。"""
```

### 2. 重命名或兼容

两种路径：

**路径 A（最小改动）**：保留 Middleware 类名，增加新钩子方法，所有默认为空操作。现有中间件不用改，自动兼容。

**路径 B（语义清晰）**：Middleware 改名为 Hook，提供兼容别名 `Middleware = Hook`。所有现有代码继续用 `Middleware`，新代码用 `Hook`。

建议：路径 A。Hook 只是概念名，代码里继续用 Middleware 类，只是补齐生命周期方法。

### 3. 内核调用新钩子

`core/kernel/engine.py` 或 `loop.py`：

**启动时**（Engine.__init__ 或 .create()）：
```python
for middleware in self.middlewares:
    await middleware.on_start(config)
```

**会话恢复**（每轮开始前，在现有 before 之前）：
```python
state = initial_state  # 默认新会话
for middleware in self.middlewares:
    loaded = await middleware.on_session_load(session_id)
    if loaded is not None:
        state = loaded
        break
```

**会话关闭**（DELETE 请求）：
```python
for middleware in self.middlewares:
    await middleware.on_session_close(session_id)
```

**停止时**（Engine.close() 或 api/app.py shutdown）：
```python
for middleware in self.middlewares:
    await middleware.on_stop()
```

### 4. 现有中间件不改

TraceMiddleware、HITLMiddleware、MemoryWriteMiddleware、DelegationMiddleware 都不需要改，它们只用了中间四个阶段的钩子。新钩子默认空操作。

## 第二部分：会话持久化 Capability

会话存储作为标准 Capability 实现，用 Hook 的 on_session_load、after、on_session_close 三个阶段。

### 1. 能力结构

新建 `capabilities/session_persistence/`：

```
session_persistence/
├── __init__.py
├── capability.py         # SessionPersistenceCapability
├── backends/
│   ├── memory.py         # MemoryBackend（默认）
│   ├── sqlite.py         # SqliteBackend
│   └── postgres.py       # PostgresBackend
└── config_schema.py      # SessionPersistenceConfig
```

`capability.py`：

```python
class SessionPersistenceCapability(Capability):
    def __init__(self, config: SessionPersistenceConfig):
        self.backend = self._create_backend(config)
    
    @property
    def name(self) -> str:
        return "session_persistence"
    
    def tools(self) -> list[BaseTool]:
        return []  # 不提供工具
    
    def middlewares(self) -> list[Middleware]:
        return [SessionPersistenceHook(self.backend)]
```

`SessionPersistenceHook`（Middleware 子类）：

```python
class SessionPersistenceHook(Middleware):
    def __init__(self, backend: Backend):
        self.backend = backend
    
    async def on_session_load(self, session_id: str) -> AgentState | None:
        data = await self.backend.load(session_id)
        if data is None:
            return None
        # 反序列化消息，检查悬空调用，补"未执行"结果
        messages = self._deserialize_messages(data["messages"])
        messages = self._fill_dangling_calls(messages)
        return AgentState(messages=messages)
    
    async def after(self, state: AgentState) -> AgentState:
        # 轮末写盘
        await self.backend.save(
            session_id=...,  # 从哪里拿？需要设计
            data={"messages": self._serialize_messages(state["messages"])}
        )
        return state
    
    async def on_session_close(self, session_id: str) -> None:
        await self.backend.delete(session_id)
```

### 2. Backend 接口

```python
class Backend(Protocol):
    async def save(self, session_id: str, data: dict) -> None: ...
    async def load(self, session_id: str) -> dict | None: ...
    async def delete(self, session_id: str) -> None: ...
    async def list_expired(self, retention_days: int) -> list[str]: ...
    async def close(self) -> None: ...
```

三种实现：
- **MemoryBackend**：字典，零依赖
- **SqliteBackend**：aiosqlite，文件路径来自配置
- **PostgresBackend**：asyncpg，连接串来自环境变量

### 3. 配置

`SessionPersistenceConfig`（Pydantic）：

```python
class SessionPersistenceConfig(BaseModel):
    backend: str = "memory"  # memory / sqlite / postgres
    sqlite_path: str | None = None
    retention_days: int = 30
```

`agent.yml`：

```yaml

```

### 4. session_id 传递问题

`after` 钩子需要知道当前 session_id，但签名是 `after(state)`，state 里没有 session_id。

**解决方案**：用 ContextVar（现有 identity 机制）：

```python
# core/kernel/context.py
session_id_var: ContextVar[str | None] = ContextVar("session_id", default=None)

# api/sessions.py 在每轮开始时设置
session_id_var.set(session.id)

# SessionPersistenceHook.after 读取
session_id = session_id_var.get()
```

### 5. 悬空调用补结果

```python
def _fill_dangling_calls(self, messages: list[BaseMessage]) -> list[BaseMessage]:
    """工具调用没有对应结果时，补一条 ToolMessage。"""
    result = []
    pending_calls = {}
    for msg in messages:
        result.append(msg)
        if isinstance(msg, AIMessage) and msg.tool_calls:
            for tc in msg.tool_calls:
                pending_calls[tc["id"]] = tc
        elif isinstance(msg, ToolMessage):
            pending_calls.pop(msg.tool_call_id, None)
    # 剩下的是悬空的
    for call_id, tc in pending_calls.items():
        result.append(ToolMessage(
            content="因服务重启，此工具调用未执行",
            tool_call_id=call_id,
            name=tc["name"]
        ))
    return result
```

## 关键设计点

1. **Hook vs Middleware 命名**：建议保留 Middleware 类名，只是补齐生命周期方法。Hook 是概念，Middleware 是代码。
2. **on_session_load 返回值**：`AgentState | None`，和其他钩子签名不同。这是本质差异：它是创建状态，不是修改状态。文档里明确说明。
3. **session_id 传递**：通过 ContextVar，不改钩子签名。
4. **Trace 留在内核**：暂不改，留到 v1.6+。当前只做会话持久化 Capability。
