## v1.5a 通用装配

### 背景

现有 7 个能力在架构上已经是插件（PluginLoader 动态加载，内核零认知）。
两个真实缺口：

1. **外部包没有标准发现机制**：只能在配置里写模块路径，无法自动发现。
2. **api/ 认识了具体能力**：`api/sessions.py` 直接 import HITLCapability 和 MultiAgentConfig，做 isinstance 检查。第三方审批插件（如 OA 对接）无法替换内置 hitl，因为 api/ 不认识它。

### 要求

**1. entry point 分三组**

在 `pyproject.toml` 增加 `[project.entry-points]` 块，三个扩展组：

```toml
[project.entry-points."aro.capabilities"]
basic_tools    = "capabilities.basic_tools.capability:get_capability"
hitl           = "capabilities.hitl.capability:get_capability"
knowledge      = "capabilities.knowledge.capability:get_capability"
memory         = "capabilities.memory.capability:get_capability"
multiagent     = "capabilities.multiagent.capability:get_capability"
doc_generation = "capabilities.doc_generation.capability:get_capability"
mcp_client     = "capabilities.mcp_client.capability:get_capability"

[project.entry-points."aro.session_stores"]
memory   = "api.session_backends.memory:get_backend"
sqlite   = "api.session_backends.sqlite:get_backend"
postgres = "api.session_backends.postgres:get_backend"

[project.entry-points."aro.trace_sinks"]
# 预留，v1.5a 不实现 sink，只建好扩展组
```

**2. PluginLoader 改造**

`core/kernel/plugin_loader.py`：
- 加载时先查 `aro.capabilities` entry point（`importlib.metadata.entry_points`）
- 回退到现有模块路径（`capability_config[name]['module']`）
- 两种路径都通过，优先级：配置中的 module 覆盖 entry point
- 现有配置完全不变

```python
def _resolve_module(self, name: str, config: dict) -> str:
    # 1. 配置显式指定 module 优先
    if "module" in config.get(name, {}):
        return config[name]["module"]
    # 2. entry point 自动发现
    eps = entry_points(group="aro.capabilities")
    if name in eps:
        return eps[name].value.rsplit(":", 1)[0]
    # 3. 回退：约定路径
    return f"capabilities.{name}.capability"
```

**3. 服务协议：Capability.provides**

`core/kernel/capability.py` BaseCapability 增加可选属性：

```python
@property
def provides(self) -> list[str]:
    """服务名列表，如 ['approval', 'expert_catalogue']。
    api/ 按服务名查询，不 import 具体 Capability 类。"""
    return []
```

内置能力声明：
- HITLCapability：`provides = ["approval"]`
- MultiAgentCapability：`provides = ["expert_catalogue"]`

Engine 增加查询方法：

```python
def get_service(self, service_name: str) -> Capability | None:
    """Return first capability providing this service, or None."""
    return next(
        (c for c in self.capabilities if service_name in c.provides), None
    )
```

**4. api/ 去除对 capabilities.* 的直接依赖**

`api/sessions.py`：
- 删除 `from capabilities.hitl.approval_manager import ApprovalManager`
- 删除 `from capabilities.hitl.capability import HITLCapability`
- 删除 `from capabilities.multiagent.handle import ...`
- 改用 `engine.get_service("approval")` 和 `engine.get_service("expert_catalogue")`
- 通过服务协议的接口方法（已在 HITLCapability、MultiAgentCapability 上）访问功能

**5. 边界测试**

`tests/core/kernel/test_import_boundary.py` 增加：

```python
def test_api_does_not_import_capabilities():
    """api/ must not import capabilities.* directly."""
    # 同现有 LangGraph 边界测试，AST 扫描 api/ 目录
```

### 不改的部分

- 内核（loop.py、engine.py 核心逻辑、middleware.py）不改
- 现有 capabilities/ 实现不改
- 现有配置文件不改
- get_capability 工厂函数签名不变

## v1.5b 会话持久化

建在 v1.5a 之上。会话存储后端通过 `aro.session_stores` entry point 注册，配置里写后端名即可。

### 存储后端接口

新建 `api/session_backends/base.py`：

```python
class SessionBackend(Protocol):
    async def save(self, session_id: str, data: SessionData) -> None: ...
    async def load(self, session_id: str) -> SessionData | None: ...
    async def delete(self, session_id: str) -> None: ...
    async def list_expired(self, retention_days: int) -> list[str]: ...
    async def close(self) -> None: ...
```

`SessionData`（dataclass）：
- `session_id: str`
- `engine_config_id: str`（指向哪个配置，用于重建引擎）
- `target_agent: str | None`
- `tenant_id: str | None`
- `user_id: str | None`
- `messages: list[dict]`（序列化的消息，含 reasoning_content）
- `created_at: float`
- `updated_at: float`
- `expires_at: float`

### 三种实现

**MemoryBackend**（默认）：包装现有字典逻辑，零依赖。

**SqliteBackend**：
- 依赖 `aiosqlite`（已在 optional-deps 或新增）
- 路径：`ARO_SESSION_STORE_PATH` 或 `~/.aro/sessions.db`
- 单表：session_id（主键）、engine_config_id、data_json、created_at、updated_at、expires_at

**PostgresBackend**：
- 依赖 `asyncpg`（新增 optional-deps `[persistence]`）
- 连接串：`ARO_DB_URL`
- 同一表结构，连接池化

### 生命周期

**写入时机**：
- 轮末（普通情况）：`await backend.save(session_id, data)`
- 每个写工具执行后（带 HITL）：立刻落盘（防止重启丢失已执行的写操作）

**恢复**：
- session_id 在内存字典里找不到，调 `await backend.load(session_id)`
- 加载 SessionData，重建引擎（从 engine_config_id 找配置），装回消息
- 检查悬空调用：消息里有 AIMessage.tool_calls 但缺少对应 ToolMessage 的，补一条：
  ```
  ToolMessage(content="因服务重启，此工具调用未执行", tool_call_id=..., name=...)
  ```

**关闭**：DELETE 请求 → `await backend.delete(session_id)` + 内存清理。

**TTL**：
- `session_ttl_seconds`（默认 3600）：内存驻留时长，到期从内存清掉，存储还在
- `session_retention_days`（默认 30）：存储保留期，后台任务定期调 `list_expired` 再 `delete`

### 配置

`api/settings.py` 增加：

```python
session_store: str = Field(default="memory")   # entry point 名
session_store_path: str | None = None           # sqlite 路径
db_url: str | None = None                       # postgres 连接串
session_retention_days: int = Field(default=30)
```

环境变量：`ARO_SESSION_STORE`、`ARO_SESSION_STORE_PATH`、`ARO_DB_URL`。

`api/app.py` 启动时：
```python
backend = load_session_backend(settings.session_store, settings)
store = SessionStore(settings, backend=backend)
```

### 序列化

消息序列化用 LangChain 内置 `messages_to_dict` / `messages_from_dict`。
必须保留：
- `AIMessage.tool_calls`
- `AIMessage.additional_kwargs["reasoning_content"]`
- `ToolMessage.tool_call_id`

序列化测试专门覆盖这三项的往返正确性。
