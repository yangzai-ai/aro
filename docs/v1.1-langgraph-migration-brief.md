# v1.1 任务说明：内核迁移到 LangGraph + 运行时上下文加固

> 本文档供 Codex 实现。**写法：重约束、轻实现**——讲清目标、边界、铁律、验收，具体实现你定。与现有契约或测试冲突时，按 CONVENTIONS 第 9.7 条先喊停给提案，不要默默改。

---

## 一、背景与动机

ARO 当前内核循环（`core/kernel/loop.py`）是**手写的 ReAct 循环**，多轮驱动在 `core/kernel/engine.py` 的 `run()` 里（`for _ in range(max_tool_rounds+1)`，直到最后一条消息不是 ToolMessage）。

项目依赖 `langgraph`，但**只用了它的 `add_messages` reducer 和 multiagent 内部的 StateGraph，主循环没走 LangGraph**。后果：白白错过 LangGraph 的 **Checkpointer（状态持久化）、中断恢复、未来长流程跨进程续跑**能力。

**本次目标**：把内核主循环迁到 LangGraph 的 StateGraph，为将来的长流程/持久化/跨进程恢复打好地基；同时顺手还两笔技术债（见第四节）。

**为什么现在做**：目前没有长流程任务，但决定提前用 LangGraph，避免将来为此重写内核。这是有意的、经过权衡的决定。

## 二、最高铁律（违反即失败）

### 铁律 1：LangGraph 只许存在于 `core/kernel/` 内部
- `capabilities/`、`projects/`、`api/` **绝不 import langgraph**
- 对能力来说，底层换没换 LangGraph **它们无法感知**
- 验证：`grep -rn "import langgraph\|from langgraph" capabilities/ projects/ api/` 必须为空（multiagent 现有的 StateGraph 用法若已存在则记录为豁免，但不新增扩散）

### 铁律 2：三个扩展点契约不改
`Middleware` 的 `before/after/before_tool/after_tool/bind_tools`、`BaseTool` 的 `name/description/usage_prompt/permission/schema/run`、`Capability` 的 `tools/middlewares/start/close` —— **一个都不动**。7 个能力和它们的测试不应因此改写。

### 铁律 3：行为对等，测试全绿
迁移是"换引擎"，不是"改功能"。现有全部测试（除非测的是 loop.py 内部实现细节）必须继续通过。对外行为（CLI、API、SSE、HITL、Trace、多 Agent）保持一致。

### 铁律 4：范围克制
只做"主循环迁移 + 两笔债"。**不**趁机做：长流程调度、分布式、时间旅行 UI、PTC 模式等。Checkpointer 接上、留好接口即可，不实现完整的跨进程恢复 UI（真有需求时再做）。

## 三、主循环迁移（核心任务）

### 现状要吃透（迁移前必读这几处）
- `core/kernel/loop.py::run_once` —— 单轮：before 钩子 → LLM(流式/非流式) → 工具执行(含 before_tool 拦截、write/HITL 保护、after_tool) → after 钩子
- `core/kernel/engine.py::run` —— 多轮驱动（`for range(max_tool_rounds+1)`，直到最后一条不是 ToolMessage）；`trace_middleware.start/finish`（TraceMiddleware 被引擎特殊对待，非普通中间件）；`event_scope(on_event)`
- `core/kernel/events.py` —— `emit_event` + `event_scope`（ContextVar）
- `core/kernel/streaming.py::collect_stream` —— 流式增量拼接
- HITL：`capabilities/hitl/` 用 `before_tool` 拦截 + `ApprovalManager` 的 Future 挂起

### 迁移要求
1. **用 LangGraph StateGraph 重写内核循环**（agent 节点 + tools 节点 + 条件边：有 tool_calls 去 tools 节点，否则 END），替换 `engine.run` 里手写的 `for` 多轮循环和 `loop.run_once`。

2. **接上 Checkpointer**：用 LangGraph 的 checkpointer（开发默认 `MemorySaver`；预留 Postgres checkpointer 的切换口子，不强制实现）。thread_id 作为 checkpoint 线程标识（`context["thread_id"]` 已有）。

3. **中间件钩子映射到图的节点/钩子，语义必须保持**：
   - `before`（轮级，正序）、`after`（轮级，逆序）
   - `before_tool`（工具执行前，可拦截返回 `(False, msg)`）、`after_tool`（工具执行后）
   - **四个钩子的触发时机和顺序不能变**（HITL、Trace、memory 都依赖它们）
   - `bind_tools` 装配时注入工具表，保持

4. **流式与事件保持**：
   - SSE 的 token 流、`tool_call`/`tool_result` 事件继续发（接到 LangGraph stream 或保留 `emit_event`+ContextVar，二选一你定；但 API/前端看到的事件流不变）
   - `event_scope(on_event)` 的对外行为不变

5. **write 工具保护保持**：没有 `_handles_write` 中间件时，write 工具仍被拒绝（现 loop.py 第 133-146 行逻辑）。

6. **forbidden 工具**：仍不进 LLM 工具列表、不可执行。

7. **max_tool_rounds 上限保持**：超限仍报 "Tool-call limit reached"。

### HITL 的处理（想清楚再做）
现在 HITL 靠中间件 `before_tool` 拦截 + Future 挂起等前端 `/approve` 回调。LangGraph 原生有 `interrupt()`。

**两个选择，评估后在提案里说明选哪个**：
- (A) **保持现有 HITL 机制**（Future 挂起）：只要迁移后 `before_tool` 钩子时机不变，HITL capability 不用改 —— **优先选这个，改动最小**
- (B) 改用 LangGraph `interrupt()`：更"原生"，但要重写 HITL capability 和 `/approve` 接口，风险大

除非 (A) 在 LangGraph 下无法实现，否则选 (A)。若选 (B) 必须先喊停说明理由。

## 四、顺手还两笔技术债

### 债 1：`state["context"]` 类型化
现在 `AgentState.context` 是裸 `dict`，散落塞入 `thread_id`、`tenant_id`、`user_id`、`trace_id`、`tool_call_id` 等，无契约、无类型，排查困难（engine/loop 里多处 `setdefault("context", {})`）。

**改法**：定义类型化的 `RuntimeContext`（TypedDict 或 Pydantic，`core/kernel/state.py` 内），明确字段。各处裸操作收敛到统一构造/访问。
- **不改变能力读取方式**（能力还是读 `state["context"]["xxx"]`，只是 xxx 有了类型保证）
- 允许保留一个 `extra` 字段放未定型临时数据，避免过度僵化

### 债 2：运行时注入机制收敛（评估后按需做）
现在能力拿运行时信息有三套机制：`bind_tools`（工具表）、`ContextVar` scope（memory/multiagent 身份）、`state["context"]`（thread_id 等）。

**要求**：先评估能否在不改能力契约前提下收敛（如统一用类型化 context 承载身份，减少 ContextVar 特设用法）。
- 能干净收敛且不动契约 → 做
- 会牵动多个能力契约或风险大 → **不做**，提案里说明，记为后续
- **优先级低于债 1 和主循环迁移**，不要为它冒险

## 六、验收标准

### 行为对等
- CLI（`python -m projects.helpdesk.main --offline-demo`）输出一致
- Web 工作台：查询/更新(HITL审批)/报告/历史 全部正常
- SSE：token 流式、tool_call/tool_result 事件、approval_required 一致
- 多 Agent 委派正常，Trace 贯穿
- forbidden 不可调用、write 无 HITL 时被拒

### 架构铁律
- `capabilities/ projects/ api/` 零 langgraph import（grep 验证）
- 三个扩展点契约签名未变
- 能力代码、能力测试未因迁移改写（除非契约确需变更且已喊停确认）

### 质量
- 全量 pytest 绿（数量不少于迁移前；新增 checkpointer/图的测试）
- ruff + mypy 通过
- Checkpointer 能存取状态（至少 MemorySaver 验证一个 save/load）

### 文档
- 迁移提案 + 验收报告
- 更新内核运行时相关描述（docs/design/ 下补或更新"内核运行时说明"）
