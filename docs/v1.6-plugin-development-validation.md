## 交付范围

- capabilities/session_persistence/：标准 Capability、Hook、严格配置与 Backend 协议，Memory/Sqlite/Postgres 三实现，无业务工具。
- initialize 同步校验配置/选择未连接 backend，on_start 异步初始化，after 按模型轮保存，on_session_load 恢复，on_session_close 按显式选项删除（默认保留），on_stop 释放，Capability.close 幂等兜底。
- LangChain messages_to_dict/messages_from_dict，快照 version=1；reasoning_content 留在 additional_kwargs，不进入 content；tool_calls 与 ToolMessage 完整往返，context 与顶层 tenant_id 均保存。
- 恢复修复悬空调用时按批次插入 status=error 的“执行状态未知”结果，已有结果不改，不执行工具；歧义结果/空或重复 ID 拒绝恢复。
- TTL 以最后 save 的 UTC Unix 秒为准，load 不返回过期数据；initialize 使用带 updated_at 条件的原子 DELETE 清理过期记录。无后台定时任务，不跨 backend 自动迁移。
- SQLite 使用真实 aiosqlite、原子 autocommit 参数化 SQL；PostgreSQL 使用 asyncpg 池、参数化 SQL，连接串仅来自 ARO_DB_URL，连接/命令/关闭超时限制 30 秒，异常对外脱敏。数据库 updated_at 使用 REAL/DOUBLE PRECISION 的 UTC Unix 秒数，而非依赖数据库时区的 TIMESTAMP。
- pyproject 可选 session-sqlite/session-postgres 依赖组，开发用 asyncpg-stubs；注册 aro.capabilities 的 session_persistence 工厂入口。未启用插件、Memory 选择均不加载数据库驱动。
- 新增 Helpdesk 只读模拟配置 projects/helpdesk/config/agent_session_persistence.yml；README 和能力文档给出安装、配置、受信身份恢复与边界说明。

## 限定与运维说明

默认关闭保留数据；显式删除开关会在 API 过期/退出或 Engine 正常关闭时删除记录。只交付插件级恢复，浏览器旧 ID 仍 404；不新增 API 鉴权/恢复入口，不宣称恢复审批或检查点续跑。

after 是模型轮级，可能已经保存中间工具轮；取消/断连不代表外部操作未执行或未保存。恢复缺结果只代表执行状态未知。新建 MockRepository 也不会恢复业务源数据。

同一 thread_id 必须由宿主授权与互斥；本插件没有跨进程会话锁或多 worker 协调。存储为明文 JSON 运行数据，部署方负责权限、加密、备份；不同应用使用独立 schema/存储路径及一致保留策略。配置切换不是数据迁移。

不做可选 Trace 包装或权限清单，不删除 Middleware 兼容别名，不引入新扩展点。仅把获批的 context 入口绑定补入框架，其余为标准插件代码。
