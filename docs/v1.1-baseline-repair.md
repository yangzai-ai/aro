## 剩余 6 个失败与根因

| 测试（均在 tests/api/test_workbench.py） | 证据与根因 |
| --- | --- |
| test_scenes_consistency_ownership_and_report_download | 重复查询执行成功，但 panel.duplicate_check 为 None。EvidenceTool 判断 `check_duplicate`，实际工具名为 `check_duplicate_tickets`；此外它取 ticket_id，而实际参数是 title/category。 |
| test_render_cancel_publication_read_expiry_and_cleanup | 渲染 worker 未启动。项目 ticket.docx 仍要求航空字段，helpdesk 数据被文档服务的必填校验拒绝，无法进入目标取消路径。 |
| test_disabled_project_imports_in_fresh_interpreter | workbench.py 顶层导入 capabilities.doc_generation.public；报告禁用也加载文档能力。独立解释器的禁用不加载断言失败。 |
| test_http_repository_report_reads_only_public_facts | projects/helpdesk/repositories/http.py 不存在；create_repository 的 production 分支为 NotImplementedError。原测试使用类对象占位且注释掉 HTTP 调用断言，无法验证真实公开事实路径。 |
| test_expired_session_cleans_report_and_panel | 报告生成失败，无 artifact，后续索引失败。 |
| test_completed_approval_survives_later_llm_failure | 已完成写入的状态断言通过，后续报告生成抛出 Required template data unavailable。 |

模板实测变量：`aircraft_id, approval_history, approval_reason, approval_time, area, conflict, declaration_id, generated_at, limitation, operator, plan_time, source, status`。

而 `Workbench.generate_report` 提供 `ticket_id/title/description/category/priority/status/requester/assignee/...`，两者不匹配。不能往测试塞航空字段或替换成无关模板来让取消测试表面通过。

另一个需要在模板修正后复核的点：`ReportParameters` 未禁止 extra 字段。目前伪造报告测试通过时，模板失败也会导致无产物，因此**尚不能证明拒绝额外字段有效**。修复模板后必须重新核验这项安全断言，不能以当前通过结果替代。
