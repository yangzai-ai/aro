# v1.5 框架通用化

> 供 Codex 实现。回归两个扩展点架构：BaseTool + Hook（完整生命周期）。
> 原则：一个内核，两个扩展点，Capability 打包器无特例。

日期：2026-11-10。前置：v1.4（031165f）。理由见 decisions-v1.4.md D2。

---

## 背景

v1.5 的目标是**让框架变得通用，能够支持各种各样的插件**。之前讨论中发现设计逐渐复杂化，准备为会话存储和 Trace 单独建扩展组。这偏离了最初的**一个内核、两个扩展点（BaseTool + Hook）**设计哲学。

核心澄清：会话持久化、Trace 等所有能力都能基于这两个扩展点实现。现有 Hook 只覆盖轮级钩子（before/before_tool/after_tool/after），缺少装配期和关闭期钩子。补齐后，框架能支持任意能力，不需为具体插件写特例。

**与 v1.6 的分工**：v1.5 是框架改造，v1.6 才是具体插件开发（会话持久化、其他能力实现）。

---

## 三大改造任务

### 任务 1：Entry Point 自动发现

使用 Python `importlib.metadata` 实现插件自动发现。

#### 1.1 定义 Entry Point 组

在核心框架文档和代码中定义：

```python
# core/kernel/discovery.py

CAPABILITY_ENTRY_POINT_GROUP = "aro.capabilities"
```

第三方包通过在 `pyproject.toml` 中声明：

```toml
[project.entry-points."aro.capabilities"]
session_persistence = "aro_plugin_session_persistence:SessionPersistenceCapability"
trace_extended = "aro_plugin_trace:TraceCapability"
```

#### 1.2 实现发现机制

`core/kernel/discovery.py`：

```python
from importlib.metadata import entry_points
from core.kernel.capability import Capability

def discover_capabilities() -> dict[str, Capability]:
    """
    从 entry points 加载所有 Capability 插件。
    返回 {name: capability_instance} 映射。
    """
    discovered = {}
    group = entry_points().select(group="aro.capabilities")

    for ep in group:
        try:
            capability_class = ep.load()
            # Capability 类需提供无参数或配置文件初始化
            instance = capability_class()
            discovered[ep.name] = instance
        except Exception as e:
            # 日志记录加载失败，继续下一个
            logger.warning(f"Failed to load capability {ep.name}: {e}")

    return discovered
```

#### 1.3 集成到 Engine

`core/kernel/engine.py` 或初始化流程：

```python
from core.kernel.discovery import discover_capabilities
from core.kernel.capability import Capability

class AgentEngine:
    def __init__(self, agent_config, capabilities: list[Capability] | None = None):
        # 显式传入优先
        if capabilities is None:
            capabilities = list(discover_capabilities().values())

        self.capabilities = capabilities
        # ... 后续初始化
```

#### 1.4 配置文件支持

`agent.yml` 可显式声明启用哪些能力：

```yaml
capabilities:
  session_persistence:
    backend: sqlite
    sqlite_path: ~/.aro/sessions.db
  trace_extended:
    enabled: true
```

加载时，框架匹配已发现的 entry point，用配置初始化 Capability 实例。

#### 1.5 兼容现有方式

现有代码依然支持直接 import 和传入 Capability 对象，不强制用 entry points。

### 任务 2：Hook 完整化（补齐生命周期）

现有 Hook 只有中间四个阶段。补齐装配期和关闭期钩子。

#### 2.1 完整 Hook 协议

修改或扩展 `core/kernel/hook.py`（或 `core/kernel/middleware.py`）：

```python
from typing import Protocol

class Hook(Protocol):
    """完整生命周期钩子。所有方法可选，默认空操作。"""

    # ===== 装配期 =====
    async def on_start(self, config: dict) -> None:
        """引擎启动时：配置校验、连接建立、资源初始化。
        在第一轮执行之前调用，全局只调一次。"""

    # ===== 轮级钩子 =====
    async def on_session_load(self, session_id: str) -> AgentState | None:
        """轮开始前（新增）：会话恢复。
        返回 AgentState 或 None。内核遍历所有 Hook，
        第一个返回非 None 的即用，其余跳过。"""

    async def before(self, state: AgentState) -> AgentState:
        """每轮开始（现有）：轮前处理。"""

    async def before_tool(
        self, tool_name: str, tool_args: dict, state: AgentState
    ) -> tuple[bool, str | None]:
        """工具执行前（现有）：权限检查、参数验证。
        返回 (允许, 拒绝原因)。"""

    async def after_tool(
        self, tool_name: str, tool_args: dict, tool_result: ToolResult, state: AgentState
    ) -> AgentState:
        """工具执行后（现有）：结果验证、Trace 记录。"""

    async def after(self, state: AgentState) -> AgentState:
        """每轮结束（现有）：写盘、Trace 导出。"""

    # ===== 关闭期 =====
    async def on_session_close(self, session_id: str) -> None:
        """会话关闭时（新增）：清理会话数据（如删除存储记录）。"""

    async def on_stop(self) -> None:
        """引擎停止时（新增）：连接释放、资源清理。
        与 on_start 对称，全局只调一次。"""
```

#### 2.2 内核调用时机

`core/kernel/engine.py` 或 `api/app.py` 中添加调用：

**启动时**（Engine.__init__ 或 .create()）：
```python
for hook in self.hooks:
    await hook.on_start(config_dict)
```

**会话恢复**（每轮开始前，在现有 before 之前）：
```python
state = initial_state  # 默认新会话
for hook in self.hooks:
    loaded = await hook.on_session_load(session_id)
    if loaded is not None:
        state = loaded
        break
```

**会话关闭**（DELETE 请求 `/sessions/{session_id}`）：
```python
for hook in self.hooks:
    await hook.on_session_close(session_id)
```

**停止时**（Engine.close() 或 api/app.py FastAPI shutdown 事件）：
```python
for hook in self.hooks:
    await hook.on_stop()
```

#### 2.3 现有 Hook 兼容性

TraceHook、HITLHook、MemoryWriteHook、DelegationHook 都不需要改。它们只实现中间四个阶段，新钩子方法默认为空操作（Protocol 中不要求实现）。

### 任务 3：api/ 边界清理

移除 api/ 对 capabilities/ 内部类型的直接引用，统一通过 Capability 基类接口。

#### 3.1 现状诊断

读取 `api/` 下的文件，找出所有 `from capabilities.* import` 语句。

预期问题：
- `api/sessions.py` 可能直接引用 `MemoryWriteHook` 等具体类
- `api/trace.py` 可能直接引用 `TraceHook` 或 trace 数据结构

#### 3.2 重构原则

**禁止**：`api/` 不应知道 `capabilities/` 中的具体 Hook、Tool 类名。

**允许**：`api/` 只调用 Capability.tools() 和 Capability.hooks() 接口。

#### 3.3 重构步骤

1. **定义服务接口**（如需要）

   如果 api/ 需要 trace 数据，在 `core/kernel/` 中定义协议：

   ```python
   # core/kernel/trace.py

   class TraceService(Protocol):
       """Trace 查询接口（v1.5 不实现，仅定义）"""
       async def get_trace(self, trace_id: str) -> dict | None: ...
   ```

   Engine 持有 TraceService 实例（如有）。

2. **移除直接导入**

   查找 `from capabilities.trace import TraceHook` 等，改为：
   ```python
   # 从 Engine 获取
   trace_service = engine.trace_service
   ```

3. **测试兼容性**

   运行现有测试套件，确保 api/ 的公开接口不变。

#### 3.4 不涉及的范围

- `core/` 内部可以引用 capabilities/
- 项目层（`projects/aviation/`）可以自由导入 capabilities/
- 只是 `api/` 层需要隔离

- 现有配置文件兼容

---

## 关键设计点

1. **Entry Point 是可选的**：框架同时支持显式传入 Capability 列表和自动发现
2. **on_session_load 是特殊的**：返回值是 AgentState 而非修改，这是本质差异
3. **session_id 从何而来**：on_session_load 和 on_session_close 的 session_id 由调用方提供，通常从请求路径解析
4. **不实现具体插件**：v1.5 只改框架，会话持久化等具体实现留给 v1.6
