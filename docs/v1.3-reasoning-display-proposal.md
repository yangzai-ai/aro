# v1.3 思考展示：模型协议冲突提案（9.7 暂停）

日期：2026-11-05。状态：方案 A 已由用户确认；受限协议回传按用户明确的三条件实施。下文保留提案时的分析。

## 已核实事实

当前配置模型为 `deepseek-v4-pro`（只读取配置确认模型名，未输出密钥）。`core/llm/openai_provider.py` 的 `enable_thinking` 默认为 True，两种请求路径都会发送 `thinking.type=enabled`。框架工具会通过 tools 参数提供给模型。

DeepSeek 官方 [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode) 当前说明：

> If the request carries the tools parameter: the reasoning_content of all previous turns should be passed back to the API and will be concatenated into the context.

工具调用章节还明确：不正确回传 reasoning_content 会返回 400。规则按请求是否携带 tools 区分，并不只适用于最终实际发生工具调用的回复。

官方原始页面已保存到本地忽略目录 `tmp/v1.3-reasoning-official.html`。此证据说明协议要求；没有冒称已向当前模型端点复现 400。兼容中转服务的实际行为也不能代替官方兼容性约束。

当前实现：Provider 已读取 reasoning；collect_stream 没有转发它，KernelLoop 仅构造正文 AIMessage，消息转换器也不回传 reasoning_content。因此新增显示事件本身可以保持不回灌，但无法同时承诺 DeepSeek 思考模式的工具/多轮协议兼容。

## 冲突

任务要求“思考不回灌模型”，并要求按所用模型官方文档处理工具轮次。对于当前模型的思考模式 + tools，两项不能同时满足。按任务简报第 2 条与工程约定 9.7 暂停，不默默放宽要求、不禁用工具、不自动关闭思考。

## 方案 A：允许受限的协议字段回传（建议）

澄清“不回灌”的边界：思考绝不拼入 content、提示词、工具参数或 Trace.agent_response，但允许模型协议要求的独立 reasoning_content 字段。

- 前端展示仍使用独立 reasoning SSE，经过统一脱敏；正文及 Trace 正文保持纯回答。
- 为明确要求该字段的模型保存独立协议元数据，在 Provider 边界按文档回传，不对所有 OpenAI 兼容服务无条件发送。
- 此方案涉及模型消息元数据保留与 Provider 请求组装，超出纯展示；模型识别/显式策略配置及流式保留位置需要单独批准后细化，不在本提案中宣称已经设计完成。
- 除回传范围外，保持任务要求；三个扩展契约不变。

代价：必须放宽“任何思考均不回传”的字面要求，并补严格测试证明只出现在协议字段，覆盖工具轮次与跨轮行为。

## 方案 B：严格零回传

保留 reasoning 仅供 SSE 和浏览器本地历史；服务端模型 messages 不保存思考。

当前 DeepSeek 思考 + tools 组合不纳入兼容承诺。需要由用户明确选择可满足零回传的模型/模式；不能靠暗中关闭思考、删工具或在失败后降级来通过验收。若选择禁用思考，则这类请求没有思考块，不能用占位内容模拟。

代价：当前配置无法按官方协议同时完成思考展示和工具闭环，真实验收模型/模式需要调整。

## 冲突解除后的展示实现范围

1. collect_stream 将非空 reasoning_delta 单独转发为 reasoning；非流式 reasoning_content 整段发送，均不拼入正文。
2. 专家直连复用同一事件；委派转发为带 agent_name 的 agent_reasoning，与总控分开呈现。
3. 每条助手消息持有独立思考展示数据；没有内容不渲染。流式展开、正文开始折叠、用户可手动展开，耗时来源于实际事件时间，不猜测服务端模型计算时间。
4. 本地历史保留展示数据并校验；reasoning 与 token 同走 encode_event 脱敏。
5. 测试覆盖事件顺序、内容/Trace 隔离、委派来源、真实 React 折叠及无思考不显示；按确认后的协议方案补消息回传断言，再跑全量、mypy、Ruff、前端测试/构建及真实模型验证。

确认结果：用户选择 A，允许 AIMessage.additional_kwargs 保留思考元数据；仅 DeepSeek + enable_thinking + 实际请求携带 tools 时作为独立 reasoning_content 回传。R1 已另获最小修正授权：两条路径均先转换工具，再按实际工具列表决定 tools_present。没有改变默认模型、思考开关或三个扩展契约。
