# v1.1 任务说明：主图接入 Checkpointer（Phase 1 收官）

> 供 Codex 实现。**重约束、轻实现**。与现有契约/测试冲突按 CONVENTIONS 9.7 先喊停。
> 范围裁定以 `docs/v1.1-scope-decision.md` 第 5 条为准，优先于任何更宽泛表述。

## 一、目标与边界

把 LangGraph 的 checkpointer 接入已迁移的内核主图（`core/kernel/loop.py` 的 StateGraph），
作为**将来 interrupt / 长流程 / 跨进程恢复的地基**。本步**不**交付恢复功能。

- 默认 `MemorySaver`，**每 Engine 持有一个**，跨该 Engine 的多轮 `run()` 复用。
- `thread_id` 取自 `context["thread_id"]`（engine.run 已 setdefault）。
- 留 **Postgres 切换口子**：Engine 可接收任意 langgraph `BaseCheckpointSaver`，默认 `MemorySaver()`。
- **不做**：`interrupt()`、自动重放、自动恢复写操作、跨进程恢复 UI、时间旅行、YAML 持久化配置。

## 二、铁律（照旧）

1. **langgraph 只在 core/kernel**：checkpointer 接线写在 `engine.py` + `loop.py`。
   `grep -rn "import langgraph\|from langgraph" capabilities/ projects/ api/` 仍只允许既有 4 个豁免文件，不得新增第 5 个。
2. **三个扩展契约不改**：BaseTool / Hook / Capability 签名语义一个不动；7 个能力及其测试不因此改写。
3. **行为对等，测试全绿**：当前基线 **242 passed、3 skipped**，接入后不得减少。对外行为（CLI/API/SSE/HITL/Trace）不变。
4. **范围克制**：只接 checkpointer + 留切换口子，不顺手做别的。

## 三、必须处理对的三个技术点

### 1. 方案 A 下这是"地基"，不是功能
主图跑到底、不 interrupt。图级 checkpointer 当下**无功能收益**，是为将来 interrupt（Plan B）预埋。
文档和验收**不得**声称已实现恢复/续跑。调用方的 `AgentState` 仍是唯一权威状态；**本步绝不从 checkpointer 回读来驱动 `run()`**。

### 2. 编译带 checkpointer ⇒ 每次 invoke 必须带 thread_id
一旦 `graph.compile(checkpointer=...)`，`ainvoke` 的 config 缺 `configurable.thread_id` 会直接报错。
现状：`_run` 的 config 只有 `recursion_limit`；`run_once` 在测试里用 `AgentState(messages=[])`（无 context/thread_id）直接调。
**要求**：thread_id 推导必须无缝——有则用 `context["thread_id"]`，无则本次运行生成一个（与现 engine 行为一致），
保证 `run_once` 及所有既有测试在不改测试的前提下继续绿。不要求调用方先塞 thread_id。

### 3. 全量状态传递 vs LangGraph resume 语义
内核每轮把**完整 business 状态**作为 LastValue 通道传入（`business=frame.state, calls=[], rounds=0`）。
Engine 持有的 saver + 同一 thread_id 跨轮复用时，LangGraph 第二轮会先 load 上轮 checkpoint、再把本轮输入作为 LastValue **覆盖**。
**要求**：验证这一覆盖语义产出与现在**逐字节等价**的行为（business/calls/rounds 均被本轮输入覆盖，不残留上轮）。
`recursion_limit` 是单次 invoke 内计数，确认接入后仍正确限界、业务上限错误仍先于 LangGraph 递归错误抛出。

### 4. 既有 PostgreSQLCheckpointer 正交，别强合并
`capabilities/hitl/checkpointer.py::PostgreSQLCheckpointer` 是手工 save/load 整块 state 的独立组件，
**不是** langgraph 的 `BaseCheckpointSaver`，形状不同。图的 Postgres 切换口子应指向 langgraph 原生
`langgraph.checkpoint.postgres.PostgresSaver`。两者正交，本步**不动** `PostgreSQLCheckpointer`，不强行让它充当图 checkpointer。
若评估认为必须统一（会牵动接口），按 9.7 喊停说明，不要默默改。

## 四、接入位置

- `AgentEngine.__init__/create`：新增 `checkpointer: BaseCheckpointSaver | None = None`，默认构造 `MemorySaver()`，Engine 持有。
- `KernelLoop._run`：`graph.compile(checkpointer=...)`，`ainvoke` 的 config 补 `configurable.thread_id`（按技术点 2 推导），保留 `recursion_limit`。
- `run_once` 单轮门面保持可用。
- checkpointer 的注入路径不得要求能力感知 langgraph。

## 五、验收

- 全量 **≥ 242 passed、3 skipped、0 failed**；新增 checkpointer 测试：
  - 至少一个 save/load 往返（MemorySaver 存入后能取回该 thread 的 _GraphState）。
  - 多轮对话接入 checkpointer 后与未接入**行为等价**（消息序列、最终答复一致）。
  - `run_once` 无 thread_id 场景仍绿（证明推导无缝）。
- 全范围 mypy 仍 **9 项既有**，无新增；ruff 改动范围通过。
- langgraph 扫描：仍只 4 个豁免文件 + 内核，无第 5 个能力文件。
- 三个扩展契约签名未变；能力代码/能力测试未因此改写。
- 文档：记录接入方式、"地基非功能"的明确边界、Postgres 切换口子位置；不夸大为已实现恢复。
