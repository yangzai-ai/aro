# v1.3 专家直连与示例清理任务说明

> 供 Codex 实现。**重约束、轻实现**。目标：实现专家智能体真·直连交互 + 清理 helpdesk 示例冗余。

## 背景

v1.2 前端重构后专家功能半成品：
- 专家列表存在但无会话时 404（`/agents` 过度校验）
- "向该专家提问"只是填建议词，不是真跳转选中
- **缺"选中专家后绕过总控直连"路径**——所有对话都进主会话，专家只能由总控 LLM 调 `delegate_agent` 间接触发

用户诉求的三种交互：
1. **列表显示专家 + 发起对话** → 跳对话框并选中该专家
2. **未选专家** → 总控意图识别 + `delegate_agent` 转发（已支持✅）
3. **选了专家** → **绕过总控直连该专家**（缺口❌）

同时 `projects/helpdesk/` 有 13 个配置、测试仅真正引用 7 个，难懂。需精简 + 补说明文档。

## 一、专家直连机制（核心功能）

### 1.1 架构设计

**核心判断**：专家直连 = 把专家提升为**一等公民会话**（与主会话平级），各自独立 thread、多轮、Trace、HITL。

```
当前架构（仅总控路由）:
  用户 → 主会话(总控 Agent) → delegate_agent 工具 → 临时子引擎(用完即焚)

目标架构（增加直连路径）:
  用户 → chat(target_agent=None) → 主会话(总控)            ← 路径 1(不变)
                                       ↓ delegate_agent
                                   临时子引擎

  用户 → chat(target_agent="xxx") → 专家常驻会话(独立 thread) ← 路径 2(新增)
```

**关键点**：
- 专家会话与主会话**平级**，各自 `thread_id`、`SessionStore` 管理、资源生命周期
- 专家仍通过 `AgentRegistry` 登记，`/agents` 列出名册供前端选择
- 主会话的 `delegate_agent` **保留**（总控自主路由场景），与直连路径并存

### 1.2 后端改动

#### A. 全局专家目录（`api/sessions.py` + `api/app.py`）

**问题**：当前 `/agents` 从"某个会话的 engine"读 `MultiAgentCapability`，要求会话已存在。但专家目录是配置层的，首屏就该能看，不依赖会话。

**改法**：
1. `SessionStore.__init__` 增加 `experts: list[AgentDescription]` 属性（从配置读，固定不变）
2. API 启动时，若配置含 `multiagent` 能力，提取 `registry.catalogue()` 存入 `store.experts`；否则空列表
3. `/api/helpdesk/agents` 改为 `return store.experts`，删除 `owned(x_aro_session)` 校验

**效果**：无会话时也能列专家；所有会话共享同一专家目录（符合单配置 API 架构）。

#### B. chat 支持目标专家参数（`api/app.py`）

**`ChatInput` 增加字段**：
```python
class ChatInput(BaseModel):
    message: str
    session_id: str | None = None
    target_agent: str | None = None  # 新增：专家名，None=主会话，有值=直连该专家
```

**路由逻辑**（`/chat` 处理）：
```python
if body.target_agent:
    # 路径 2：直连专家
    # 1. 从 store.experts 校验该专家存在（不存在报 400）
    # 2. 构造专家会话 ID：f"{body.session_id or generate()}:expert:{body.target_agent}"
    #    （与主会话 ID 区分，支持同时存在主会话 + 多个专家会话）
    # 3. reserve 专家会话（engine 从专家配置创建，独立 thread_id）
    # 4. 进入专家 engine 的消息循环，SSE 流式返回
else:
    # 路径 1：主会话（原逻辑不变）
    session = await store.reserve(body.session_id)
    # ... 原有流程
```

**专家会话创建**（`SessionStore.reserve` 扩展）：
- 识别会话 ID 格式：`<base>:expert:<name>` → 专家会话
- 专家会话的 `engine` 构造：从专家的 `AgentHandle.engine_scope()` 获取**常驻引擎**（不再"用完即焚"），存入 `sessions` 字典，生命周期与主会话一致（过期 TTL、手动关闭均适用）
- 专家会话的 `thread_id` 独立：`f"expert-{name}-{base_session_id}"`

**难点处理**：
- 专家当前是 `LocalAgentHandle`，`engine_scope()` 返回临时 `AsyncIterator`。改为支持**常驻模式**：新增 `persistent=True` 参数，返回的 engine 不自动关闭，由 `SessionStore` 管理生命周期。
- 或：专家会话创建时直接调 `AgentEngine.create(load_llm_config(), expert_config)`，不走 `AgentHandle`（更直接，`AgentHandle` 仍用于总控的 `delegate_agent`）。

### 1.3 前端改动

#### A. 专家列表"发起对话"真跳转（`Sidebar.tsx` + `App.tsx`）

**当前**：`onExpert` 只是填 `"请让 {expert.description} 协助："`，不跳转、不选中专家。

**改为**：
```tsx
// Sidebar.tsx: 按钮文案改"发起对话 ↗"
<button onClick={() => onExpert(expert)}>发起对话 ↗</button>

// App.tsx: onExpert 逻辑
const handleExpert = (expert: Expert) => {
  setTab('history');  // 切回对话 tab
  setNavOpen(false);  // 收起侧边栏
  setSelectedExpert(expert.name);  // 新增 state: 选中的专家名
  // 可选：预填提问建议，或直接发空消息建立专家会话
};
```

#### B. 对话框增加专家选择器（`ChatWindow.tsx`）

**UI**：输入框上方加一行芯片/下拉：
```
[总控助手 ▾] [ticket_analyst] [knowledge_expert]
```
- 默认"总控助手"（`selectedExpert = null`）
- 点专家名切换，选中态高亮
- 选中专家时，输入框 placeholder 改为"向 {专家名} 提问..."

**发送逻辑**：
```tsx

    sessionId.current || null,

```

### 1.4 验收

- **首屏无会话**：刷新页面，专家 tab 直接显示两个专家卡片（不报 404）
- **发起对话**：点"发起对话"，跳到对话框、专家选中态高亮、输入框 placeholder 变化

- **会话隔离**：主会话 + 两个专家会话可同时存在、各自 Trace/HITL

## 常见问题
- **"会话已过期"**：API 会话 TTL 默认 3600 秒，环境变量 `ARO_API_SESSION_TTL_SECONDS` 调整
- **报告生成失败**：检查 `capability_config.workbench.reports` 是否配置；模板字段见 `templates/README.md`
- **知识库无结果**：确认 `docs/` 下有 .md 文件；重建索引需重启或调 indexing API
