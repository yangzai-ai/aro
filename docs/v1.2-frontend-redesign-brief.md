# v1.2 前端重构任务说明：智能体工作台 + 一键换肤

> 供 Codex 实现。**重约束、轻实现**。目标：把前端从三栏态势台重构为 WorkBuddy/豆包式智能体工作台，
> 支持主题 + 业务预设换肤。范围 = **诚实可用版**：亮着的按钮必须真能用；后端暂不支持的功能预留位置并明确标"规划中/禁用"，
> **严禁假按钮**（CONVENTIONS 第 5/9 条：禁止"看起来实现了其实是空壳"）。

| 功能 | 档位 | 实现方式 |
|------|------|----------|
| 新布局（左导航 + 对话 + 可折叠证据区） | ✅ 真 | 纯前端 |
| 一键换肤（主题 + 业务预设） | ✅ 真 | 纯前端 + localStorage |
| 新建会话 | ✅ 真 | 现有 `reset()` + DELETE session |
| 流式对话 / 停止 | ✅ 真 | 现有 `streamChat` |
| HITL 审批卡片 | ✅ 真 | 现有 `submitApproval` |

| 工单面板（今日工单/计数/选中/重复/产物） | ✅ 真 | 现有 panel 接口（注意：面板需按真实字段，见第四节） |

## 一、布局（WorkBuddy/豆包式）

```
┌─────────────────────────────────────────────────────────────┐
│ 顶栏：品牌 | 主题切换 | 业务预设▾ | 连接状态 | 令牌(可选)      │
├──────────────┬──────────────────────────────┬───────────────┤
│ 左导航(可折叠)│  对话主区                     │ 证据区(可折叠) │
│ [+ 新建会话] │  消息流(markdown + 流式)      │ Trace/工单面板 │
│ ──────────── │                               │ /知识引用/报告 │
│ 选项卡:      │                               │                │
│  · 会话历史  │                               │                │
│  · 专家列表  │  ┌─ 输入区 ─────────────────┐ │                │
│ ──────────── │  │ 快捷输入 chips           │ │                │
│ (历史/专家   │  │ [多行输入框]             │ │                │
│  列表内容)   │  │ 🎤语音 📎附件(禁) 🤖专家 │ │                │
│              │  │ 模型▾(禁)        [发送]  │ │                │
│              │  └──────────────────────────┘ │                │
└──────────────┴──────────────────────────────┴───────────────┘
```

- 左导航与右证据区**均可折叠**（窄屏/专注模式）；窄屏下证据区默认收起，可抽屉弹出。
- 选项卡切换"会话历史 / 专家列表"，内容区在下方。新建会话常驻顶部。
- 响应式：≥1200px 三栏；中等屏两栏（证据区抽屉）；移动端单栏 + 顶部菜单。
- 可访问性：键盘可达、`aria-label`、焦点可见、对比度达标。

## 二、换肤系统（主题 + 业务预设）

两个正交维度，组合生效，均存 `localStorage`，首屏按保存值渲染（无闪烁）：

1. **主题**：亮 / 暗（可留"跟随系统"）。用 CSS 变量，不写死颜色。
2. **业务预设**：一组品牌风格，至少内置 3 套——`IT 支持`（青绿，默认）、`客服`（暖橙/蓝）、`通用`（中性）。
   每套预设定义一组 token：主色、强调色、圆角密度、字体族/字号密度、面板风格。

**实现要求**：
- 所有颜色/圆角/间距/字体走 `:root` 的 CSS 自定义属性（token）。组件只引用 token，不写死值。
- 暗色在 `@media (prefers-color-scheme: dark)` + `[data-theme="dark"]` 下重定义 token；业务预设用 `[data-preset="xxx"]` 切换 token 组。
- 顶栏提供主题开关 + 业务预设下拉；切换即时生效、刷新保持。
- **为开源者留扩展点**：把 token 定义集中在一个文件（如 `theme.css` 或 `theme.ts`），加注释说明"复制一组 `[data-preset]` 即可加自己的皮肤"。README/前端 README 补一句如何加皮肤。
- 现有 `dark` 布尔开关（App.tsx:26）并入新主题机制，不要两套并存。

## 三、组件架构与技术约束

- 保持 **React 18 + Vite + TS**，不引入重型 UI 框架（不加 MUI/antd 等）。可加轻量工具，但先问必要性。
- 现有真实逻辑**全部复用**，只重组 UI：`client/api.ts`（streamChat/submitApproval/projectRequest）、`client/types.ts`、
  SSE 事件处理（session/token/tool_call/tool_result/approval_required/done/error）、审批、Trace、下载、令牌、generation/epoch 竞态防护。
  **这些是已验证的正确逻辑，不要重写其语义**，只把它们接到新组件。
- 建议组件拆分：`layout/`（AppShell/Sidebar/TopBar）、`chat/`（ChatWindow/MessageList/Composer/QuickInput/VoiceButton）、
  `evidence/`（TracePanel/TicketPanel/Sources/Artifacts）、`experts/`（ExpertList）、`history/`（SessionHistory）、`theme/`（预设定义 + 切换 hook）。
- TypeScript strict 下零 `any` 滥用；`npm run build`（`tsc -b && vite build`）必须通过。
- 会话历史的 localStorage：存 `{id, title(首条用户消息截断), updated, preset}` 列表 + 每会话转录；读写包 try/catch，私密模式/禁用存储时降级为"仅当前会话"，不报错。

## 四、工单面板按真实后端字段（修复既有航空残留）

**此项与开源准备简报第 2 项是同一处**——当前 `SituationPanel.tsx` 是航空形状（declarations/aircraft_id/telemetry/flight_area），
与真实后端 `projects/helpdesk/workbench.py::panel()` 返回**对不上**。重构必须按真实字段重做工单面板：

真实 `panel()` 返回：`source, observed_at, tickets[], counts{open/assigned/in_progress/resolved/closed}, selected(工单详情), history, duplicate_check, artifacts[]`；
工单字段见 `projects/helpdesk/repositories/base.py::Ticket`（id/title/description/category/priority/status/requester/assignee/created_at/updated_at/resolved_at）。
面板渲染：今日工单列表、五状态计数、选中工单详情、`duplicate_check` 重复检查证据、`artifacts` 报告产物（下载沿用现有逻辑）。
去掉一切 aircraft/telemetry/flight_area/conflict/declaration/pending-approved-rejected 航空语义。
`isSituation` 类型守卫按新字段重写并改名（如 `isPanel`）。

## 五、专家列表的后端胶水（🟡 档，做成真的）

multiagent 能力（registry/catalogue/supervisor/delegate_agent）**已存在且已收口**，但**未接入任何 helpdesk 配置**。补三件事让专家列表成为真功能：

1. **示例专家**：在 `projects/helpdesk/` 下加 1-2 个只读示例专家（实现 `get_agent(config)->AgentHandle`，可复用 `LocalAgentHandle` 包一个只读 helpdesk 子 Agent，如"知识库专家""工单分析专家"）。只读，符合 `LocalAgentHandle` 的 read-only 约束。
2. **启用配置**：新增 `projects/helpdesk/config/agent_workbench_experts.yml`（或在现有 workbench 配置基础上）启用 `multiagent` 能力，`capability_config.multiagent.agents` 指向上面的专家工厂。确认该配置能启动、`delegate_agent` 工具可用。
3. **列目录接口**：在 `projects/helpdesk/api.py` 加 `GET /api/helpdesk/agents`（带 `require_auth`，与 panel 同款 owned-session 校验），返回当前会话引擎里 `MultiAgentCapability.registry.catalogue()` 的 `[{name, description}]`；未启用 multiagent 时返回空列表（不报错）。前端据此渲染专家列表；空列表时显示"当前配置未启用专家智能体"。

> 专家"选择"语义诚实：前端点专家 = 把"请让 {专家描述} 处理：…"带入提问；真实委派由 LLM 通过 `delegate_agent` 自主发起。**不承诺点击=直连该专家**，避免假象。
