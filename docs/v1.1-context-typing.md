## 内部结构和访问方式

`core/kernel/state.py` 新增 `RuntimeContext(TypedDict, total=False)`，字段如下：

| 字段 | 类型 |
| --- | --- |
| thread_id、trace_id、tool_call_id、parent_thread_id | str |
| tenant_id、user_id | str 或 None |
| delegation_depth | int |
| extra | dict[str, Any] |

内核通过 `runtime_context(state, create=False)` 取得已知字段视图；需要写入且 context 可能缺失时显式传 `create=True`。engine 创建缺失 thread_id、loop 写 tool_call_id、Trace 写 trace_id 和读调用标识均使用这一入口。

```python
context = runtime_context(state, create=True)
context["tool_call_id"] = tool_id
```

只有统一函数边界包含两处 cast：新建 RuntimeContext 到公开字典，以及遗留字典到内部类型视图。没有运行时转换、序列化或复制既有映射，不添加 type: ignore，不在调用点散布 cast。静态类型检查能约束内核已知字段的写入，但不声称验证了宿主身份。

兼容语义：

- 只读访问缺失 context 时，不向 state 写入新字段。
- 写入缺失 context 时创建空字典，不创建默认用户或租户。
- 已有 context 保留同一对象；未知键和嵌套对象引用不变，不迁入 extra。
- None、空字符串、错误类型等既有输入保持原值，继续交给原能力的身份校验；不自动转换成有效身份。
- 顶层 tenant_id 与 context 内身份发生冲突时，原能力仍按原逻辑拒绝。
