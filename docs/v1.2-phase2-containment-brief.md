# v1.2 Phase 2 任务说明：能力层 langgraph 收口（严格零 import）

> 供 Codex 实现。**重约束、轻实现**。与现有契约/测试冲突按 CONVENTIONS 9.7 先喊停。
> 本轮目标：达成 `scope-decision.md` 承诺的 v1.2 验收——`capabilities/`、`projects/`、`api/` **零 langgraph import**。
> 用户已就两处设计岔路拍板，见第三节。

## 一、目标与现状

Phase 1 已把主循环迁入 StateGraph 并接入 checkpointer，langgraph 当前被囚禁在 `core/kernel/` + **4 个登记豁免能力文件**：
- `capabilities/memory/capability.py`（`BaseStore` 类型注解）
- `capabilities/memory/store.py`（`BaseStore` / `InMemoryStore`）
- `capabilities/multiagent/supervisor.py`（单节点 `StateGraph` 派发图）
- `capabilities/hitl/checkpointer.py`（`PostgreSQLCheckpointer`，手工 `empty_checkpoint` 存取）

本轮把这 4 处清零。完成后：
`grep -rn "import langgraph\|from langgraph" capabilities/ projects/ api/ tests/` **必须为空**（含 tests）。

## 二、铁律

1. **三个扩展契约不改**：BaseTool / Middleware / Capability 签名语义一个不动。
2. **行为对等**：对外行为（CLI/API/SSE/HITL/Trace/多 Agent/memory）保持一致。能力的**公开 API 签名不变**：
   - `MemoryCapability(config, *, backend=...)` 仍接受注入式后端。
   - `Supervisor(registry).invoke(request, context)` 签名与返回不变。
3. **全量测试不减**：当前基线 **247 passed、3 skipped**。删除死代码（hitl checkpointer）会减少其独占测试，这是预期；除此之外总通过数不得下降，且无跳过凑数。
4. **范围克制**：只做这三处收口，不顺手重构别的。

## 三、三处收口的既定方向（用户已确认）

### A. memory —— 收进内核中立 Store 协议（核心工作）
在 `core/kernel/` 定义**中立键值存储抽象**（协议/ABC，命名如 `KVStore`），覆盖能力实际用到的操作：
`aput(namespace, key, value)`、`asearch(namespace, *, limit, offset)`（返回项需暴露 `namespace`/`value`，形状中立，不泄漏 langgraph item 类型）。
- 内核提供**进程内默认实现 + 工厂**（`shared_store(name)` 迁入内核，底层用 langgraph `InMemoryStore` 绑定，**绑定只在内核**）。
- `capabilities/memory/store.py`、`capability.py` 改为**只从 `core.kernel` import 中立协议/工厂**，删除所有 `from langgraph...`。
- 将来 Postgres/其他后端的绑定点落在内核，能力无感。
- **语义逐字保持**：精确命名空间检索（`item.namespace != namespace` 的子命名空间排除逻辑必须保留）、分页扫描、bounded output、无去重。

### B. multiagent —— 直接去掉 StateGraph，内核不留派发层
`supervisor.py` 的单节点图（`START→dispatch→END`，dispatch 内仅 `await handle.invoke`）**无功能收益**。
- 去掉 `StateGraph`/`compile`/`DispatchState`，`Supervisor.invoke` 改为**直接 `await handle.invoke(...)`** 并保留现有的 `AgentResult.model_validate` + 身份校验（`agent_name` 一致性）。
- 删除 `from langgraph...` import。`Supervisor(registry).invoke(request, context)` 对外签名与行为不变。
- 不在内核新增派发适配层。

### C. hitl —— 删除死代码 + 对应测试
`capabilities/hitl/checkpointer.py::PostgreSQLCheckpointer` 从未被框架接入（仅 `test_checkpointer.py` 引用），职责已被 Phase 1 内核原生 `BaseCheckpointSaver`/`AsyncPostgresSaver` 注入口取代。
- 删除 `capabilities/hitl/checkpointer.py` 与 `tests/capabilities/hitl/test_checkpointer.py`。
- 确认无其他引用（已核：无）。删除后 hitl 能力其余部分（ApprovalManager/中间件/capability）不受影响。
