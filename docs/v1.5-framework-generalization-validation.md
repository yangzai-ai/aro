## 三项交付

1. **Entry Point 发现**：core/kernel/discovery.py 定义 aro.capabilities，支持名称过滤、配置、strict 与资源所有权登记。Engine 按配置逐项发现，优先级为显式 Capability 列表（包括 []）> module > entry point > 旧模块约定。安装不等于启用；选中插件失败不静默换实现。配置保留旧列表/独立配置格式，增加映射归一化与重复配置拒绝。异步 create 回滚包含前序对象与 initialize 失败的对象。
2. **Hook 生命周期**：保留 ABC，新增四个默认方法。create 返回前等待 on_start；同步构造在首次 run 前启动。每个用户轮在追加输入前加载，首个非 None 胜出；校验消息结构、context、thread_id/tenant_id/user_id 和顶层 tenant，避免恢复记录覆盖宿主身份。会话关闭通知与引擎停止清理幂等、取消安全；失败不跳过剩余资源。
3. **API 边界**：api 中具体能力 ImportFrom 从 **6 条到 0 条**（含 TYPE_CHECKING）。core/kernel/services.py 定义中立审批/专家目录类型协议。API 使用 Hook.provides 查询审批，HITL 打包器仅增加服务元数据，HITLHook 不改。专家目录由 projects/helpdesk/services.py 适配并显式注入宿主，首屏不启动专家；既有直连只读/审批模式/会话归属约束保持。无需 TraceService。

API 还对新增会话关闭回调异常做逐会话隔离：过期/退出清理不能因一个回调失败而遗弃其他会话。显式关闭仍返回清理失败，批量清理记录异常类型并继续。

## 保持不变与限制

逐字节核对 core/tools/base.py、core/kernel/capability.py、core/kernel/loop.py、core/kernel/trace.py、capabilities/hitl/hook.py、capabilities/memory/hook.py、capabilities/multiagent/supervisor.py 与基线一致。BaseTool、Capability 基类、四个既有 Hook 实现和图执行过程不改；依赖文件未改，没有新增插件实现。

用户 run 的公开签名不变，新增的加载入口使用 state.context.thread_id；框架只提供机制，不声称已实现持久化、跨进程恢复或审批续跑。推荐资源型部署使用异步 create；同步构造不提供无法 await 的资源回滚保证，仍禁止装配需异步 Capability.start 的能力。工厂在返回实例前分配资源又失败时，由工厂负责其内部回滚。

服务协议是两个扩展点下的宿主类型边界，不是新插件组。通用 API 不注入专家目录时为空，Helpdesk 项目入口显式注入以保留既有专家功能。
