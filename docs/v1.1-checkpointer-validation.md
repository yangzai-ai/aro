## 接入方式

- AgentEngine.__init__/create 增加可选关键字 checkpointer，默认每 Engine 构造一个 MemorySaver，跨该 Engine 的 run 复用；旧调用方式不变。
- Engine 显式向 KernelLoop._run 传 saver，图使用 compile(checkpointer=saver)。run_once 没有新增必填参数；独立调用会用临时 MemorySaver。
- _run 通过 RuntimeContext 入口读取 thread_id；缺失时生成 UUID 写回。invoke config 同时带 configurable.thread_id 和原 recursion_limit。
- business/calls/rounds 每次从调用方完整输入初始化。没有业务层 checkpoint load，没有 ainvoke(None)、interrupt、重放、自动恢复或工具重试。
- Engine 关闭时通过既有共享清理任务删除自有内存 saver 的线程记录；外部注入 saver 的连接、关闭及数据清理归调用方负责，不删除其已有记录。
- 不改 capabilities/hitl/checkpointer.py 的 PostgreSQLCheckpointer；它与主图原生 saver 正交。

**这是快照地基，不是恢复功能。** LangGraph 的内部 load 属于 saver 协议，新 invoke 的完整输入覆盖旧通道；run 的唯一业务权威输入仍是调用方 AgentState。不能凭 saver 中有快照就宣称能够恢复审批、续跑或跨进程恢复写操作。

## 原生 PostgreSQL 口子

构造和 create 的 BaseCheckpointSaver 注入口位于内核。异步图需要实现异步 saver 方法，后续内核侧装配可以使用原生 AsyncPostgresSaver，而不要求能力导入 LangGraph。

本机同步原生 PostgresSaver 的 aget_tuple 继承基类并抛 NotImplementedError；异步调用应使用同家族 `langgraph.checkpoint.postgres.aio.AsyncPostgresSaver`。宿主必须保持数据库连接上下文覆盖 Engine 的全部运行与关闭，负责 setup、连接退出及数据保留。本轮未增加 YAML 配置、数据库连接或真实 Postgres 验收。

## 新增验证

新增 tests/core/kernel/test_graph_checkpointer.py，共 5 项：

1. 默认 saver 每 Engine 独立；实际 aget_tuple 读回 _GraphState 的消息、context、calls、rounds。不同线程/Engine 隔离，多等待者 close 后自有快照清空。
2. run_once 输入无 context/thread_id 时自动生成；有 thread_id 时保留。证明实际快照按推导的线程存取。
3. 同线程连续三轮对话，将接 saver 与去掉 saver 的同图执行比较；每轮 messages_to_dict 以固定 JSON 编码转 bytes，逐字节相等，最终回答一致。
4. 工具产生副作用后 after_tool 抛错，实际 checkpoint 留有旧 calls；新 run 用同线程空历史输入，结果只含新请求及新回答，旧 calls 不再执行、旧业务键不残留、rounds 重置。外部 saver 在 Engine.close 后仍保留记录。
5. 异步 create 使用注入的原生 MemorySaver；关闭时不调用外部 saver 的删除方法，真实记录可读回。

既有图回归不改：N=0/1/8/12 的轮次上限和原错误文本、ContextVar 跨节点及并发隔离、取消 Future 回收、消息对象引用/删除、状态替换后的 Trace 收尾。既有 run_once、HITL、memory、多 Agent 与 SSE 用例继续运行。
