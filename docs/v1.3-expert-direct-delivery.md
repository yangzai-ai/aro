## 实现

- `/api/helpdesk/agents` 读取部署配置生成的全局目录，保留 Bearer 认证，不再依赖任何会话。启动时仅装配目录，不启动专家或加载模型权重。未启用 multiagent 时返回空目录。
- ChatInput 新增可选 target_agent；省略/null 保持总控路径，指定已登记名称则创建或继续该专家的独立常驻会话。未知目标/错配会话返回 400，过期 ID 返回 404，互斥冲突返回 409。
- 使用服务器生成的不透明 UUID，避免简报示意拼接 ID 的长度、伪造和反复拼接问题。前端分别保存各对象的会话 ID；续聊必须传回同一 target_agent。主会话与专家各占一个容量名额，彼此没有父子生命周期关系。
- SessionStore 持有既有 LocalAgentHandle.engine_scope 的资源作用域，关闭时退出一次。关闭等待者取消不放弃清理；并发关闭共用任务。未给 AgentHandle 新增 persistent 参数，三个扩展契约、Engine、core、multiagent 能力均未修改。
- 直连与已有本地委派保持只读限制：发现专家装配 write 工具时拒绝启动并释放引擎。两个示例专家分别是 ticket_analyst、knowledge_expert；知识专家实际启用 knowledge + helpdesk_tools，白名单包含检索与三个业务只读工具。
- 前端卡片切回会话 tab、收起导航并选中目标；输入框上方提供总控/专家芯片、选中态及目标 placeholder，streamChat 传递 target_agent。切换对象恢复该对象最近未关闭记录，转录保留 targetAgent；旧版历史默认总控。
- 专家不具有工作台面板，前端明确显示该限制，不调用面板来误判专家会话过期。专家历史在下一次发送时由服务端验证有效性；更新和报告须切回总控。保留既有 SSE、审批、下载和 generation 竞态保护。

## 真实联调证据

后端为 `projects.helpdesk.api:app`，配置 agent_workbench_experts.yml，端口 8000；前端 Vite 5173。

1. 无会话读取目录 200，包含两位专家。
2. ticket_analyst 两轮使用同一 session_id：先查 TKT-001，第二轮从上下文回答刚关注的工单；工具调用直接为 query_tickets，不经过总控 delegate_agent。
3. knowledge_expert 首次真实检索发现本地 helpdesk_kb 尚未入库，返回检索失败，助手没有编造来源。随后执行既有 index_helpdesk_docs 脚本，向该集合入库 3 个片段，**未删除既有集合或数据**。
4. 入库后重新直连知识专家，search_knowledge_base 成功，回答引用 `common_issues.md / Email Access`；第二轮复述建议并保留来源，session_id 相同。使用本地模型与真实知识检索路径。
5. 总控请求委派时，Trace 实际出现 delegate_agent；保留专家独立 mock 快照限定。三个对象的会话 ID 独立，测试请求结束后逐个 DELETE 关闭均 200。
6. UTF-8 真实 CLI 使用保留的 agent.yml：查询 → 更新 TKT-001 为 resolved → y/Approved → 复查 resolved；进程退出码 0。

真实模型用于上述请求，但业务 Repository 仍为 mock，不代表企业业务上游已经验收。
