## 冲突一 公开 union 使既有能力新增类型错误

按原提案第 7 节，草案在 state.py 定义 RuntimeContext，并将 AgentState.context 标注为 `RuntimeContext | dict[str, Any]`。engine/loop/trace 改用统一访问函数，旧映射不复制，未知键、对象引用、None 和无效身份不转换。

内核四个改动文件的 mypy 与 ruff 均通过，但全范围 mypy 从既有 9 项变为 10 项，新增：

```text
capabilities/multiagent/supervisor.py:101:
Argument "tenant_id" to "AgentContext" has incompatible type
"str | Any | None"; expected "str"
```

原因：该能力从 context 读取 tenant_id，原 dict 的 Any 掩盖了 Optional；增加 TypedDict union 后 mypy 会检查 None 分支。能力原运行时校验拒绝 None，不能为消除类型错误而给它填入 local 或强制 str()。也不能只看内核 mypy 通过就忽略新出现的能力错误。

**建议确认的最小调整**：本阶段保持公开 `AgentState.context: dict[str, Any]` 的原注解，RuntimeContext 用于内核已知字段的构造/访问/写入；遗留字典与类型化视图仅在统一访问函数边界处理。不改能力或测试，不加 ignore，不改变身份校验、未知键位置、顶层 tenant_id 语义。严格封闭公开字段留后续。此项偏离原提案中的 union 标注，先确认再实施。

证据：`tmp/v1.1-context-mypy.txt`；内核独立命令 `python -m mypy core/kernel/state.py core/kernel/engine.py core/kernel/loop.py core/kernel/trace.py` 通过。

- tests/api/test_chat.py::test_session_capacity_and_expiry
- tests/api/test_knowledge.py::test_default_api_cold_overlap_sharing_sources_and_session_isolation
- tests/api/test_memory.py::test_api_new_session_memory_and_identity_boundary，两项参数

对照验证：保存四个 context 草案文件原始字节，临时写入基线提交中四个文件的内容，单独运行上述五项；结果 **5 failed**，失败位置与草案相同。finally 恢复草案文件原字节。未改 API 实现或现有测试。

**建议确认的最小补修**：仅将这五项涉及的测试过期时间设置为 `time.monotonic() - store.settings.session_ttl_seconds - 1`（或等价的确定性时钟夹具），保留全部会话移除、客户端关闭和共享资源归零断言。单独验证并作为基线稳定性补充提交，与 context 提交分开；不改生产 TTL 或 expire 行为，不等待系统运行满一小时，不靠环境改时钟宣称通过。
