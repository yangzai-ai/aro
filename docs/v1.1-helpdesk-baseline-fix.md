## HTTP 适配约定与验证边界

这次恢复的是项目层 HTTP 实现，未新增业务工具或修改 Repository 签名。上游接口使用以下映射：

| 方法 | HTTP 请求 | 响应 |
| --- | --- | --- |
| query_tickets | GET tickets，query 为非空的 status/priority/category/assignee | Ticket 数组 |
| get_ticket | GET tickets/{编码后的 ticket_id} | Ticket 对象；404 表示不存在 |
| update_ticket | PATCH tickets/{编码后的 ticket_id}，JSON 为非空的 status/assignee/priority | 更新结果对象，透传工具 |
| get_ticket_history | GET tickets/{编码后的 ticket_id}/history，query 为 limit | TicketHistory 数组 |
| check_duplicate | GET tickets/duplicates，query 为 title/category | Ticket 数组 |

路径相对于配置 base_url，保留 base_url 的服务前缀。连接和读取使用既有 timeout。除单工单读取允许 404 外，其余 HTTP 错误不转换成“无数据”。未添加重试或自动恢复写操作。

配置仍使用已有字段：`data_source: production`、`base_url: <业务服务地址>`、`timeout: 10`。工作台模块仍为 `projects.helpdesk.workbench`；reports 继续按原配置选择启用。

HTTP 测试使用 httpx.MockTransport，未连接公司业务系统，未声称完成真实生产 HTTP 联调。报告测试返回单个工单对象，匹配 get_ticket 的真实响应；原调用路径、公开事实读取、转义断言均保留。
