# v1.1 范围决定（用户已确认，2026-11-02）

> 本文件是对 `v1.1-langgraph-migration-brief.md` 和 `v1.1-migration-proposal.md` 的**最终裁定**，优先级高于任务书里与此冲突的表述（尤其铁律 1 的"严格零 import"措辞）。

## 分两步走

**第一轮（现在做，本次任务）**：
1. **先修测试基线**（最优先）——当前 35 failed、183 passed、3 skipped。这些失败是 aviation→helpdesk 改造时测试层残留的航空断言（`pending/approved` 旧状态、`query_flight_ticket` 旧工具名、UAV/DECL 数据、航空知识库问题），**不是迁移引入的**。先单独修到全绿，作为迁移前后对照基线。
   - 只改测试里的航空残留断言，对齐 helpdesk 真实状态/工具名/数据
   - 保留安全语义（身份隔离、禁用不加载、审批归零、资源清理），不降低断言强度、不删测试凑数
   - 标注"基线修复"，与迁移分开 commit
2. **主循环迁移到 LangGraph**：按提案第 3 节的 StateGraph 结构（agent/tools/after + 条件边），替换 engine.run 的 for 多轮循环；保留 `KernelLoop.run_once` 单轮门面。
3. **context 类型化（债1）**：按提案第 7 节，`RuntimeContext` + 阶段性兼容输入（接受既有 dict 输入，内核写入用类型）。
4. **HITL 用方案 A**：保持 Future 挂起，不改 ApprovalManager/HITL Hook/审批 API，不用 interrupt()。
5. **Checkpointer**：默认 MemorySaver，每 Engine 持有，留持久化切换口子；不自动重放、不自动恢复写操作。
6. **债2（运行时注入三合一）不做**：提案第 8 节已论证三者职责不同，本轮保留，留待后续。

**第二轮（v1.2，以后单独做）**：严格收口——把以下 4 处既有 langgraph 用法收进 core/kernel，能力只通过中立适配层调用，达成"能力零 langgraph import"。本轮**不做**，避免与主循环迁移叠加风险。
