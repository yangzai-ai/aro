# v1.3 工作台显示思考过程

> 供 Codex 实现。重约束、轻实现。契约冲突按 CONVENTIONS 9.7 喊停。

## 现状（已核实）

- `core/llm/openai_provider.py` 已读出 `reasoning_content`（非流式）和 `reasoning_delta`（流式，约 270/291 行）。
- `core/kernel/streaming.py::collect_stream` 只转发 `delta` 为 `token` 事件，**丢弃了 `reasoning_delta`**。
- 前端没有处理任何 reasoning 事件，所以只显示正文。

## 要求

1. **后端事件**：`collect_stream` 把非空 `reasoning_delta` 转发为新事件 `reasoning`（字段 `delta`），和 `token` 平行，不并进正文。非流式路径若有 `reasoning_content`，按同一事件语义整段发出一次。
2. **不回灌**：思考内容不得进入发给模型的 `content`，也不进 Trace 的 Agent 正文。DeepSeek 思考模式下，多轮/工具调用轮次对 `reasoning_content` 的回传有自己的规则：按当前所用模型的官方文档核实后处理；行为不明确就按 9.7 喊停，不要猜。
3. **专家直连与委派**：直连专家会话一样转发 `reasoning`。委派子 Agent 的思考按现有事件转发方式标记来源（如 `agent_reasoning`），不要混进总控的思考。
4. **前端**：每条助手消息上方放一个可折叠的「思考过程」块。流式时展开并实时追加，正文开始后自动折叠，可手动展开；显示耗时（如"已思考 6 秒"）。样式走主题 token，亮/暗和各预设都要清楚可读。本地会话历史一并保存思考内容。
5. **诚实**：模型不返回思考内容时（非推理模型），不显示这个块，不放空壳、不放占位。
6. **SSE 脱敏**：`reasoning` 事件同样走 `encode_event` 的密钥脱敏。

## 验收

- 用会返回思考内容的模型实测：思考块流式出现 → 正文开始后折叠 → 可展开；不返回思考的模型不出现该块。
- 后端有测试覆盖：reasoning 事件发出、不进入消息 content、和工具调用交错时顺序正确。前端测试覆盖折叠与"无思考不渲染"。
- 全量 pytest ≥ 257 passed、mypy 0、ruff 通过、前端测试与 build 通过。
- 单独 commit，完成后暂停复验。
