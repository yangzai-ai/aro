# v1.4 工具执行管线加固：交付与验证

日期：2026-11-06。基线：`88e3861`。状态：自测完成后提交独立复验；不代替用户验收。

## 实现范围

- `core/kernel/loop.py`：进入工具批次前深拷贝全部调用；每个 before_tool 收独立参数副本，run 收独立执行副本；事件也收副本。
- after_tool 逐个隔离参数、ToolResult 与消息视图。返回状态的 context 等字段保留，但消息改写丢弃，真实消息对象身份保留；context/外部写入允许且不做事务回滚。
- after_tool 普通异常不阻断观察链、结果事件与后续调用。每个 Trace 工具记录的 `hook_errors` 保存 hook_class/hook/error_type，不保存原始异常文本；取消不吞掉。
- `BaseTool.timeout_seconds` 默认 None。仅 `tool.run()` 在 asyncio.timeout 内，无审批截止、无自动重试。超时变失败结果并继续批次。
- Trace 工具记录、SSE tool_result、前端 ToolStep 增加授权和执行耗时；总耗时继续保留。工作台执行记录分别显示授权/执行耗时和观察钩子异常。
- 更新 CONVENTIONS 第 5 节与 kernel-runtime 说明。没有新增依赖、装配入口或能力开关。

## 耗时口径

`duration_ms` 计完整工具管线（截至观察链结束）；`execution_duration_ms` 只计 run（含取消收尾），未执行为 0。write 调用实际到达通用 `_handles_write` 授权钩子时，`approval_duration_ms` 计整个 before_tool 阶段，包含阶段内其他钩子；拒绝/授权异常也记录。未走审批为 None。Trace 与 SSE 使用同一组耗时数值。

## 边界核对与实际限制

- Hook/Capability 契约文件与 Engine 未修改；BaseTool 只增加简报授权的可选 timeout_seconds。Trace 四个既有钩子实现 AST 与基线一致，补全工作在内核私有完成函数进行；HITL、Memory、Delegation 的实现不改。
- capabilities/projects/api/tests 无 LangGraph import 新增（扫描为空），不增加能力层依赖。
- 超时是协作式异步截止：阻塞事件循环、吞取消的工具没有硬截止保证，已发生的外部写入不会自动回滚。副本隔离也不是对任意 Python 插件的进程沙箱；通过其他持有引用或外部副作用破坏状态不属于本次边界。
- 不测试或宣称检查点恢复/续跑；不改审批 Future 机制。未做真实外部业务写入或浏览器人工验收。
- 暂存只含本任务代码、测试、文档；不纳入 .env/models/.venv/data/node_modules/tmp 或构建产物。独立提交后暂停，不推送、不打 tag。
